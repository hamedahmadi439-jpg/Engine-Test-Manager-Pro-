# Engine Test Manager Pro 2.3

نسخه ۲.۳ بر پایه سورس ۲.۲ ساخته شده و ساختار دیتابیس قبلی را حفظ می‌کند. هنگام اجرای نخستین نسخه ۲.۳ روی دیتابیس ۲.۲، مهاجرت افزایشی انجام می‌شود و سوابق قبلی حذف نمی‌شوند.

## تغییرات نسخه ۲.۳

1. **سطح دسترسی مدیر و اپراتور:** مدیر به همه شیفت‌ها، سوابق و مدیریت کاربران دسترسی دارد. اپراتور فقط شیفت‌های باز متعلق به حساب خودش را می‌بیند. شناسه کاربر مالک شیفت در دیتابیس ثبت می‌شود و مسیر بازکردن شیفت نیز کنترل دسترسی دارد.
2. **فهرست خطاهای مردودی:** خطاها در چهار گروه صوتی، نشتی، مکانیکی/مونتاژی و سنسورها دسته‌بندی شده‌اند و نوع انتخابی همراه رکورد موتور ذخیره می‌شود.
3. **صفحه‌کلید داخلی ورود:** صفحه‌کلید درون برنامه با حروف فارسی/انگلیسی، اعداد فارسی/انگلیسی، فاصله، پاک‌کردن و حذف آخرین نویسه؛ ورودی سیستم‌عامل برای فیلدهای ورود لازم نیست.
4. **نام توسعه‌دهنده:** «توسعه‌دهنده: حامد سیدفقیر» در نوار کناری درج شده است.
5. **مخفی‌سازی اطلاعات ورود مدیر:** راهنمای پیش‌فرض از صفحه ورود حذف شده و نام کاربری/رمز از پیش پر نمی‌شود. حساب مدیر پیش‌فرض حفظ شده اما هیچ رمز یا راهنمای ورود در رابط عمومی یا README نمایش داده نمی‌شود. هش‌های قدیمی در اولین ورود موفق به PBKDF2-HMAC-SHA256 با salt تصادفی ارتقا می‌یابند؛ رمز جدید کاربران نیز با همین روش ذخیره می‌شود.
6. **اسکن بارکد در پس‌زمینه:** هوک سراسری کم‌سطح صفحه‌کلید ویندوز به runner اضافه شده است. اسکنر باید پسوند Enter داشته باشد. ورودی‌های سریع و حداقل پنج‌نویسه‌ای به کانال برنامه ارسال می‌شوند و کلیدها برای نرم‌افزار تست اصلی بلعیده نمی‌شوند.
7. **تعیین وضعیت موتور قبلی:** هر اسکن به‌صورت «در انتظار» ثبت می‌شود. با اسکن موتور بعدی، قدیمی‌ترین موتور در انتظار در پنجره تعیین وضعیت برنامه نمایش داده می‌شود؛ در صورت مردودی، دسته و نوع ایراد اجباری است. اعلان ویندوز نیز برای ثبت اسکن/نتیجه ارسال می‌شود.
8. **ذخیره و خروج:** دکمه در نوار بالایی و پایین صفحه شیفت در دسترس است. موتورهای تعیین‌تکلیف‌نشده قابل تعیین وضعیت‌اند یا اپراتور می‌تواند آگاهانه شیفت را با وضعیت pending ببندد؛ رکوردها حذف نمی‌شوند.

## ساخت

GitHub Actions با Flutter stable پروژه را تحلیل می‌کند، نسخه Windows را می‌سازد و Setup.exe و Portable ZIP را منتشر می‌کند. فایل نصب‌کننده از Inno Setup ساخته می‌شود.

## نکات تست و محدودیت‌های تأییدنشده

- در این محیط Flutter/Dart SDK و Windows runtime موجود نیست؛ بنابراین اجرای `flutter analyze`، کامپایل Windows، تست نصب و تست میدانی هنوز انجام نشده است. نتیجه GitHub Actions باید سبز شود و سپس روی خط واقعی آزمایش شود.
- دریافت سراسری بارکد با سرعت ورود و پسوند Enter طراحی شده است. ابتدا با بارکدهای آزمایشی و بدون موتور واقعی تست شود؛ سرعت/چیدمان کیبورد و احتمال تداخل باید در همان سیستم خط تولید بررسی شود.
- اعلان ویندوز چهار دکمه تعاملی قبول، مردود، نیازمند بررسی و ذخیره و خروج دارد. برای گزینه مردود، پنجره انتخاب دسته و نوع ایراد باز می‌شود.
- Windows 7 به‌صورت واقعی در این محیط قابل آزمون نیست. نسخه Flutter stable فعلی عمدتاً برای Windows 10/11 هدف‌گذاری می‌شود؛ سازگاری Windows 7 را نباید تأییدشده تلقی کرد.
- حساب اولیه مدیر حفظ شده است؛ تغییر رمز مدیر پس از ورود نخست توصیه می‌شود.
